# <style> 肥大化チェックリスト

> **基本定理**: スタイルは「色・タイポグラフィ・スペーシング・共通コンポーネント」の 4 系統が
> 一元管理され、コンポーネント固有の装飾だけが scoped に残る状態が理想。

## 検出観点 (4 種)

### S1. グローバル CSS / デザイントークンへ移すべき
- **完全同一のルールセット**が複数コンポーネントで重複定義されている
  - 例: `.grow { flex: 1; min-width: 0; }` が 4 ファイル
- 頻出値がハードコードされている (font-size / gap / padding など):
  - 分布の確認: `rg -o "font-size: [0-9.]+px" src --glob "*.vue" | sort | uniq -c | sort -rn`
  - 10 箇所以上に同じ値が分散していればトークン化候補
- 推奨先: `src/styles/global.css` の `:root` に CSS 変数 (`--text-*`, `--space-*`) を定義して置換

### S2. 共通クラス / ユーティリティ化すべき
- 同一のルールセットが 3 コンポーネント以上で重複している → global.css の共通クラスへ
  - 検出例: `rg -l "\.grow" src --glob "*.vue"` (クラス名ごとに定義ファイル数を数え、3 以上なら候補)
- **global.css に既存のクラス (.row, .btn, .grow 等) が scoped で再定義されていないか**:
  - 完全同一なら scoped 定義を削除して global を使用
  - 固有ルールのみ残す (例: `.row input` は残し `.row` 本体は global に)

### S3. 子コンポーネントへ分割すべき
- 1 つの style ブロックが **300 行超**、またはレイアウト・テーマ・状態ごとに責務が混在
- ロジック (script) を分割したコンポーネントと一貫させる (style だけ取り残さない)

### S4. パフォーマンス上の問題
- セレクタが過度に深い (5 段階以上のネスト、Sass 不使用でも CSS で深い子孫セレクタ)
- 巨大なメディアクエリの重複
- `!important` の多用 (10 回以上):
  - `rg -c "!important" src --glob "*.vue"`

## 除外ルール

- コンポーネント固有の 1 回きりの装飾 (100 行未満で可読性に問題がないもの)
- 1-2 箇所のみの値 (トークン化の利益が薄い)
- ライブラリ由来のスタイルの上書き (1-2 箇所程度)

## 適用時の注意

- **トークン化は挙動不変**: 値を正規化 (4px→8px など) しない。既存値をそのまま変数に置き換える
- トークン名は既存の変数命名と整合させる (小文字ハイフン: `--text-xs`, `--space-sm` など)
- 色は通常テーマ CSS の変数 (`--primary` 等) が既にある — 色のハードコードを確認したら
  テーマ変数が既に定義されていないか先に確認する
- scoped 削除後の空 style ブロックは削除する
- 変更は 1 問題 1 コミット。対象ファイルを明示指定してステージする
