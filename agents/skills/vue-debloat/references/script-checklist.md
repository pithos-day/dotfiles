# <script> 肥大化チェックリスト

> **基本定理**: コンポーネントの script は「責務が 1 つで、短時間で理解できる」ことが目標。
> 読者が「このファイルは何をするか」を 1 文で答えられないなら、分割候補。

## A. 分離候補の判定 (3 種)

### A1. composable へ分離すべき
- 状態 (ref/reactive) + 処理が一まとまりで、**複数コンポーネントで再利用される/されうる**ロジック
- 検出パターン:
  - ドラッグジェスチャ + undo 管理の定型 (pointerdown/move/up + 初回 undo)
  - グローバルイベント (keydown / pointerdown / resize) の登録・解除の対
  - フォーム処理 (初期化・submit/cancel・バリデーション)
  - デバウンス・タイマー管理
  - メニュー・ダイアログの開閉状態管理
- 推奨先: `src/composables/use*.ts`

### A2. 素の .ts (lib/) へ分離すべき
- Vue に依存しない純ロジック:
  - 計算・座標変換・フォーマット
  - 定数テーブル (イベント種別・モード定義・表示名)
  - 型定義 (SFC から export される型は lib へ)
  - イベント走査 → 表示レコード変換
  - ヒットテスト (最近傍点探索など)
- 推奨先: `src/lib/*.ts` (Vue 非依存の純関数として)

### A3. 子コンポーネントへ分割すべき
- script が **200 行超**かつ責務が明確に複数 (例: 描画 + 編集 + プレビュー + ショートカット)
- 自己完結した UI ブロック (展開セクション・独立パネル) が 1 画面に同居している
- 推奨先: 責務ごとの子コンポーネント (props/emit で接続)

## B. 除外ルール (誤検知防止)

- canvas 描画・ポインタハンドラに密結合した小さな状態 (drag 等の ref 1 個)
- マジックナンバー 1 個程度・命名のみの問題
- 既に composables/ や lib/ に分離済みのロジック (利用のみ)
- 親子間 props/emit の受け渡しのみの軽量ラッパー

## C. 横断的重複の検出 (優先度 High)

同一パターンが複数ファイルにある場合は最優先で報告する:

```bash
# 例: 同一関数名・同一パターンの重複を検出
rg -l "setPointerCapture|beginEdit\(\)" src/components --glob "*.vue"
rg -o "font-size: [0-9.]+px" src --glob "*.vue" | sort | uniq -c | sort -rn
```

## D. 適用時の注意

- 抽出した純関数 (lib/) にはテストを追加する (テスト可能になったものはテスト対象にする)
- 過剰抽出チェック: 1 コンポーネント専用・15 行以下 → ローカル関数のまま
- 二重抽出チェック: composable 化 → さらに子コンポーネント化、の順で両方やらない
